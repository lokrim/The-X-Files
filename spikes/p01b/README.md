# P01b development instrumentation

Not an application feature or a passed gate. Normal app imports/compiler/Metro exclude this directory. The launcher requires `XFILES_P01B=1`, temporarily changes the package entry and Metro config, and backs up/restores those files plus tsconfig (which Expo may update) on exit. Never build a release while it is active. If killed without exit handlers, run `node spikes/p01b/launch.cjs --restore` before any application build/check.

Run a development client with `XFILES_P01B=1 node spikes/p01b/launch.cjs` and USB `adb reverse tcp:8081 tcp:8081`. Typecheck separately with `npx tsc -p spikes/p01b/tsconfig.json --noEmit`. The launcher also temporarily selects `./spikes/p01b/native` for Expo native autolinking; rebuild/install the **debug** client while it is active to enable the measurement module. SDK candidates are pinned by the root lockfile. All crypto, I/O and service implementations here are disposable candidates, never production adapters.

This harness measures two sequential, awaited 1 MiB SDK reads from a >=2 GB no-copy picker URI, including reopening, short terminal reads, byte counts, aggregate cache snapshots and available Hermes heap stats. Throughput includes yields/instrumentation. Direct output uses a newly SAF-created file in write-only mode; raw write timing excludes hashing. It counts a bounded read-back and separately compares SDK native streaming SHA-256 against the independent Node synthetic-data reference under test-utils, without logging a digest, then deletes the test output. Regenerate that public reference with `node test-utils/p01b/write-reference.mjs`. SDK native digest was source-inspected to stream 64 KiB, without caching/read-all. Cancellation deletes only the newly created output. Provider-specific capacity is explicitly unknown. CRC timing sums CPU-loop wall intervals excluding yields and reports separate total wall time and a two-pass decimal 2 GB CPU estimate.

`crypto.ts` compares Quick Crypto and expo-crypto against public Node/NIST AES-GCM answers, then noble and async native scrypt against RFC7914/Node answers. References and small-cost helpers stay in test-utils. It never installs global shims. Native scrypt deliberately uses 384 MiB maxmem; cancellation discards/wipes late results and waits separately for the native callback. The original collected cancel response measured two timestamps inside the abort handler and **does not establish caller-resume latency**. The corrected instrument measures after the waiting caller resumes; this correction still needs a phone rerun. Callback arrival bounds CPU completion from above; it is not an exact native CPU-stop timestamp.

The offline synthetic DocumentsProvider in `provider/` supplies non-seekable short reads, grant revocation and controlled output faults. Install its separate debug APK, start the target app, and **grant access after every force-stop/restart**, before invoking `faults` or `large`:

```sh
adb shell am broadcast -a com.xfiles.p01bprovider.GRANT -p com.xfiles.p01bprovider
node spikes/p01b/call.cjs faults
adb shell am broadcast -a com.xfiles.p01bprovider.REVOKE -p com.xfiles.p01bprovider
node spikes/p01b/call.cjs revoked
```

Verify current target UID grants independently before attributing an open/read failure to non-seekable files. The collected SDK/native open failures are **inconclusive** because the exact failure stage and grant state were not captured. The old `NON_SEEKABLE_FILEHANDLE` log label was an unsupported inference; it has been replaced with an unclassified failure code. Add allowlisted query/open/read/close failure stages before rerunning; never print raw errors/URIs. `large` applies the same bounded 2 GB read/write/count/digest/delete exercise to the local stream candidate. Faults and large-stream trials remain unfinished.

`service.ts` plus the local Kotlin module compare ordinary foreground service behavior with activating HeadlessJS on the existing ReactContext. No additional JS runtime or wake-lock permission is introduced. Progress counters advance only from actual JS-invoked bounded I/O; background polling uses the native debug status receiver, without CDP/Metro traffic driving the JS loop. The notification, cancellation, force-stop, five-minute background/lock and shortened timeout cases **have not been observed to completion**. The module compiling is not a gate pass. The maintained-library comparison is recorded in DECISIONS; no notification dependency was installed.

`memory.py` records aggregate dumpsys baselines/sampled peaks (no raw dumps); create the matching `.stop` file to finish it. `device.py` navigates known labels only, avoiding unrelated UI text/filename logs; Android picker navigation may require the phone user's help. `call.cjs` is host-only CDP control; `collect.py` extracts only this app's allowlisted aggregate events from adb. Neither belongs in app code. Results, limitations and the remaining fix plan are in DECISIONS/PROGRESS. Android17 debug results do not supply Android14/15 or identified mid-range reference coverage.

On reconnection, stop the test service with `adb shell am broadcast -a com.xfiles.P01B_STOP -p com.xfiles.app`, verify its cleanup state, remove remaining task-owned files via the harness cleanup action, reset/uninstall `com.xfiles.p01bprovider`, delete the two test notification channels, and remove USB forwarding. Restore notification permission/device_config from the captured pre-test settings, if any were changed. Then restore the normal launcher wiring, rebuild/install the normal development app to remove debug test hooks, and verify the release graph/native autolinking again. The disconnected-phone run could restore host wiring only; device cleanup is outstanding. Never claim it completed without observing it.
